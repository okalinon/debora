# 9. Збірка, тести, релізи

## Збірка

```powershell
.\build\Compile.ps1                 # → dist\Debora.ps1 + SHA256SUMS
.\build\Compile.ps1 -Exe            # + dist\Debora.exe (ps2exe)
.\build\Compile.ps1 -Sign -Cert ... # підпис Authenticode
```

Кроки `Compile.ps1`:
1. Перевірка `config/*.json` за схемами — помилка зупиняє збірку.
2. `PSScriptAnalyzer` для `src/` — помилки зупиняють збірку, попередження в звіт.
3. Конкатенація `src/` у фіксованому порядку, вбудовування JSON і XAML.
4. Запис `dist/Debora.ps1` у **UTF-8 з BOM** (PowerShell 5.1 без BOM читає файл як ANSI й ламає кирилицю).
5. Перевірка, що отриманий файл розбирається парсером PowerShell і вікно будується (`-BuildTest`).

## Тести

| Рівень | Що перевіряємо | Де |
|---|---|---|
| Схема | Кожен твік валідний, `id` унікальні, є обидві мови, `command` має `undoRun` | Pester, CI |
| Модулі дій | Для кожного типу: `Get-State` → `Invoke` → `Test` = true → `Restore` → стан як до | Pester, на тестовому ключі `HKCU:\Software\DeboraTest`, тестовій службі |
| Planner / Recommender | Правила профілів на змодельованих `SystemInfo` (HDD+4 ГБ, SSD+16 ГБ, ноутбук з батареєю) | Pester, CI |
| Журнал | Відкат у зворотному порядку; пропуск при конфлікті | Pester, CI |
| Інтеграційні | Кожен профіль на чистій ВМ: застосувати → перезавантажити → перевірити стан → відкотити | Hyper-V ВМ, вручну перед релізом |

### Матриця ВМ

| ОС | Конфігурація |
|---|---|
| Windows 10 22H2 Home | 4 ГБ RAM, HDD-подібний диск, локальний акаунт |
| Windows 10 22H2 Pro | 8 ГБ, SSD |
| Windows 11 23H2 Home | 8 ГБ, SSD, акаунт Microsoft |
| Windows 11 24H2/25H2 Pro | 16 ГБ, SSD |
| Windows 11 на непідтримуваному залізі | 4 ГБ, без TPM (встановлено через Rufus) |

Кожна ВМ має контрольну точку «чиста система» для повторних прогонів.

## CI (GitHub Actions)

- `windows-latest`: PSScriptAnalyzer, Pester (схема, модулі на тестових ключах, planner), `Compile.ps1`, артефакт `dist/`.
- Тести, що змінюють систему по-справжньому, — лише на ВМ, не в CI.
