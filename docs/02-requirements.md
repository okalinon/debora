# 2. Вимоги

Пріоритети: **M** — обов'язково для MVP, **S** — для 1.0, **C** — бажано пізніше.

## Функціональні вимоги

### Огляд системи
| ID | Вимога | Пр. |
|---|---|---|
| FR-01 | Визначати версію і збірку Windows (10/11, редакція, 22H2/24H2…) | M |
| FR-02 | Визначати тип системного диска (HDD/SSD/NVMe), обсяг RAM, процесор, наявність батареї | M |
| FR-03 | На основі заліза пропонувати профіль (наприклад, «Слабкий ПК» для HDD + ≤4 ГБ) з поясненням чому | M |
| FR-04 | Показувати вільне місце на C:, стан диска (SMART), режим BIOS (UEFI/Legacy), стиль розділів (GPT/MBR) | S |

### Твіки
| ID | Вимога | Пр. |
|---|---|---|
| FR-10 | Завантажувати твіки з `config/tweaks.json` за схемою з [Моделі твіків](04-tweak-model.md) | M |
| FR-11 | Для кожного твіка показувати назву, опис, рівень ризику й поточний стан (застосовано / ні / частково / н/д) | M |
| FR-12 | Ховати або блокувати твіки, що не підходять до ОС чи заліза (наприклад, «лише Windows 11», «лише HDD») | M |
| FR-13 | Профілі: Мінімальний, Стандартний, Слабкий ПК, Ігровий, Максимальний; вибір профілю ставить галочки | M |
| FR-14 | Попередній перегляд: перелік конкретних змін (ключ → старе значення → нове) до застосування | M |
| FR-15 | Застосування вибраних твіків з прогресом і журналом у реальному часі, без зависання вікна | M |
| FR-16 | Пошук і фільтр твіків за назвою, категорією, ризиком | S |
| FR-17 | Експорт / імпорт власного набору твіків (JSON) | S |

|---|---|---|
| FR-20 | Перелік встановлених вбудованих (Appx) застосунків з позначкою «можна безпечно видалити» | M |
| FR-21 | Видалення вибраних застосунків для всіх користувачів + заборона перевстановлення (provisioned) | M |
| FR-22 | Повернення видалених застосунків через winget / Microsoft Store | S |

| FR-24 | Оновлення всіх програм через `winget upgrade --all` | C |

| FR-71 | Оцінка 0–100 загалом і по категоріях; критична проблема обмежує загальну оцінку | S |
| FR-72 | Кожна знахідка має пояснення і спосіб виправлення (твіки, обслуговування, драйвери, посилання, інструкція) | S |
| FR-73 | «Виправити все рекомендоване» одним планом з попереднім переглядом | S |
| FR-74 | Глибоке сканування: winget, драйвери з Windows Update, SFC, фрагментація | C |
| FR-75 | Звіт HTML і JSON, порівняння «до/після» | S |
| FR-76 | Після сканування — упорядкований чекліст: що, чому, де взяти (посилання), кнопка дії, залежності між кроками | S |
| FR-77 | Пункти чекліста відмічаються автоматично після перевірки результату; прогрес зберігається між запусками | S |
| FR-78 | Чекліст можна надрукувати / зберегти HTML з посиланнями для іншого ПК | S |

## Нефункціональні вимоги

| ID | Вимога |
|---|---|
| NFR-01 | Працює на Windows 10 22H2 і Windows 11 23H2+ «з коробки»: PowerShell 5.1, без встановлення .NET/модулів |
| NFR-02 | Розповсюджується одним файлом `Debloater9.ps1` (+ необов'язковий `.exe`-обгортка) |
| NFR-03 | Запуск вікна ≤ 3 с на HDD + 4 ГБ RAM; перевірка стану всіх твіків ≤ 5 с |
| NFR-04 | Інтерфейс не зависає під час застосування (фоновий runspace) |
| NFR-05 | Кожна дія ідемпотентна: повторне застосування нічого не ламає |
| NFR-06 | Помилка однієї дії не зупиняє решту; підсумок показує, що не вдалося і чому |
| NFR-07 | Утиліта не надсилає жодних даних; мережа потрібна лише для winget і перевірки оновлень (за згодою) |
| NFR-08 | Усі рядки інтерфейсу — у файлах локалізації (`uk`, `en`) |
| NFR-09 | Масштабування інтерфейсу 100–200% DPI, світла й темна тема |
| NFR-10 | Покриття тестами (Pester): схема JSON, кожен тип дії (застосування → перевірка → відкат) |
