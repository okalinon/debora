# 11. Драйвери: перевірка та оновлення

> **Оновлено 2026-10-10:** Windows Update як джерело драйверів **не використовуємо** — замість нього власний менеджер драйверів, див. [13-driver-manager.md](13-driver-manager.md). Флешка-набір і бібліотека з цього документа лишаються в силі як одне з його джерел. Розділи нижче про Windows Update — історичні.

Мета — показати, які пристрої працюють без драйвера або з помилкою, і оновити драйвери **лише з офіційних джерел**, з можливістю повернути попередню версію.

## Головний сценарій: драйвери на свіжу Windows на будь-якому ПК

Проблема свіжої Windows: часто немає драйвера мережі (а отже, й Windows Update), а на нових ноутбуках Intel (VMD / RST) установник навіть не бачить NVMe-диск. Тому драйвери мають бути **на флешці**, а інтернет — лише додатковим джерелом.

### Флешка-набір (Driver Kit)

Одна флешка: інсталятор Windows + Debora + бібліотека драйверів.

```
USB:\
├─ sources\, boot\ ...            # інсталятор Windows (Media Creation Tool / Rufus)
├─ $WinpeDriver$\                 # драйвери, які Windows Setup підхоплює САМ під час встановлення
│  └─ <копія потрібних драйверів диска й мережі>
└─ Debora\
   ├─ Debora.ps1, run.bat
   └─ Drivers\
      ├─ Acer_Aspire ES1-522\     # набір конкретної моделі (знятий з робочого ПК)
      │  ├─ manifest.json         # модель, SKU, дата, список HWID і драйверів
      │  └─ <інфи драйверів>
      ├─ Lenovo_20XWCTO1WW\
      └─ _Common\                 # «універсальні»: Wi-Fi/LAN Intel, Realtek, Killer; Intel RST/VMD
```

### Чотири режими

| # | Режим | Коли | Як працює |
|---|---|---|---|
| 1 | **Зняти драйвери з ПК** | Перед перевстановленням, або з будь-якого налаштованого ПК тієї ж моделі | `Export-WindowsDriver -Online` (лише сторонні драйвери, без вбудованих у Windows) → `Drivers\<Виробник>_<Модель>\` + `manifest.json` з HWID пристроїв |
| 2 | **Підготувати інсталяційну флешку** | Перед встановленням на ПК, де установник не бачить диск або немає мережі | Копіює драйвери класів SCSIAdapter/HDC (диск) і Net (мережа) потрібної моделі та `_Common` у `$WinpeDriver$` — Windows Setup встановлює їх сам, без жодних дій |
| 3 | **Встановити драйвери** | Одразу після першого входу в нову Windows | Визначає модель → ставить її набір; потім проходить усю бібліотеку (`pnputil /add-driver *.inf /subdirs /install` ставить **лише ті драйвери, що підходять до наявних пристроїв** — тому бібліотека працює на будь-якому ПК); показує, що лишилось без драйвера |
| 4 | **Дотягнути з інтернету** | Коли мережа вже є | Windows Update (каталог драйверів Microsoft) → утиліта виробника → сторінка підтримки моделі |

Типовий порядок на новому ПК: **режим 3 (з флешки) → мережа запрацювала → режим 4**. Загалом 2–5 хвилин і одна кнопка «Встановити все».

### Як підбираються драйвери на «чужому» ПК

1. **Точна модель** — `Win32_ComputerSystem.Manufacturer/Model` і `SystemSKUNumber` збігаються з `manifest.json` → ставимо весь набір.
2. **Збіг за обладнанням** — для кожного пристрою без драйвера шукаємо в усіх `manifest.json` його Hardware ID (спершу точний `PCI\VEN_xxxx&DEV_xxxx&SUBSYS_…`, потім загальніший `PCI\VEN_xxxx&DEV_xxxx`) → ставимо лише знайдені INF.
3. Решта — режим 4 (інтернет) і звіт «не знайдено» з Hardware ID, щоб було що шукати вручну.

Бібліотека росте сама: кожен ПК, з якого зняли драйвери, поповнює її. Для сервісного центру це база драйверів усіх моделей, що проходили через руки.

### Повністю автоматична флешка (пізніше)

`autounattend.xml` на флешці, який Debora генерує сам:
- локальний акаунт без входу в Microsoft (той самий обхід, що й вручну, але без дій);
- після першого входу (`FirstLogonCommands`) — запуск Debora: драйвери з флешки → профіль твіків → драйвери з Windows Update.

Результат: вставили флешку, вибрали диск — і отримали готову, оптимізовану Windows з драйверами.

### Обмеження

- Драйвери з набору іншої версії Windows (10 ↔ 11) зазвичай сумісні, але не завжди — після встановлення перевіряємо «пристрої з помилкою» і пропонуємо відкат.
- `_Common` збирає користувач з офіційних сайтів (Intel, Realtek); утиліта лише підказує посилання — розповсюджувати чужі драйвери в репозиторії не будемо через ліцензії.
- Підписані драйвери обов'язкові: непідписані INF пропускаються з попередженням.

## Що перевіряємо

| Перевірка | Звідки | Що показуємо |
|---|---|---|
| Пристрої з помилкою або без драйвера | `Win32_PnPEntity`, `ConfigManagerErrorCode ≠ 0` (наприклад, 28 — драйвер не встановлено, 10 — пристрій не запускається) | Назва, ID обладнання, код помилки зрозумілими словами |
| Встановлені драйвери | `Win32_PnPSignedDriver` | Клас пристрою, виробник, версія, дата, підписаний чи ні |
| Застарілі важливі драйвери | Дата драйвера старша за 3 роки для класів Display, Net, Media, System (чипсет), SCSIAdapter/HDC (диски), Bluetooth | Лише як підказку — стара дата ≠ поганий драйвер |
| Доступні оновлення від Microsoft | Windows Update API (`Microsoft.Update.Session`, пошук `IsInstalled=0 and Type='Driver'`) | Що пропонує Windows Update, з розміром і датою |
| BIOS / UEFI | `Win32_BIOS` | Версія та дата + посилання на сторінку виробника. **Не прошиваємо** |

## Звідки оновлюємо (у порядку пріоритету)

1. **Windows Update (каталог драйверів Microsoft).** Драйвери перевірені й підписані Microsoft; встановлення через той самий API, що й «Додаткові оновлення» в Параметрах. Користувач бачить список і вибирає, що ставити.
2. **Утиліта виробника ПК**, якщо вона є і її можна запустити тихо:
   | Виробник | Інструмент | Інтеграція |
   |---|---|---|
   | Dell | Dell Command Update | CLI `dcu-cli.exe /scan`, `/applyUpdates` |
   | Lenovo | Lenovo System Update / Thin Installer | CLI |
   | HP | HP Image Assistant | CLI |
   | Acer, Asus, MSI та інші | — | Кнопка «Відкрити сторінку драйверів» для моделі |
3. **Відеодрайвери** — посилання на офіційні застосунки NVIDIA, AMD, Intel (Intel Driver & Support Assistant — через winget).
4. **Сторінка підтримки виробника** — модель визначаємо з `Win32_ComputerSystem`, формуємо посилання (для Acer: сторінка «Драйвери й завантаження» моделі).

## Чого не робимо

- Не використовуємо «пакети драйверів» і «бустери» сторонніх програм (DriverPack, Driver Booster тощо): у них часто реклама, побічні програми і невідповідні драйвери.
- Не завантажуємо драйвери з неофіційних сайтів.
- Не оновлюємо BIOS автоматично — лише показуємо версію і посилання з попередженням.
- Не ставимо драйвери «наосліп» усі одразу — тільки вибрані користувачем.

## Відкат драйверів

Перед встановленням кожного драйвера:
1. Точка відновлення (як для твіків).
2. Експорт поточного драйверного пакета: `pnputil /export-driver oemNN.inf <папка сесії>`.
3. Запис у журнал сесії: пристрій, старий пакет (`oemNN.inf`, версія, дата), новий пакет.

Відкат: `pnputil /add-driver <експортований .inf> /install` і видалення нового пакета `pnputil /delete-driver <новий oemNN.inf> /uninstall`. Якщо експорт не вдався, встановлення не починається, доки користувач явно не погодиться.

## CLI

```powershell
.\Debora.ps1 -DriverExport E:\Debora\Drivers        # режим 1: зняти драйвери з цього ПК
.\Debora.ps1 -DriverPrepareUsb E: -Model "Acer_Aspire ES1-522"   # режим 2: $WinpeDriver$
.\Debora.ps1 -DriverInstall E:\Debora\Drivers -Yes  # режим 3: встановити з бібліотеки
.\Debora.ps1 -Drivers                       # звіт: проблемні пристрої, доступні оновлення
.\Debora.ps1 -Drivers -Install All -Yes     # встановити всі оновлення драйверів з Windows Update
.\Debora.ps1 -Drivers -Install <UpdateID>   # одне оновлення
```

## Технічні нотатки

- Пошук через Windows Update займає 30 с – 3 хв і потребує інтернету — лише у фоні, з індикатором.
- Служба `wuauserv` має бути дозволена; якщо користувач поставив оновлення на паузу, пошук драйверів усе одно працює.
- `pnputil /export-driver` доступний з Windows 10 1607 — підходить для всіх підтримуваних версій.
- На етапі 3 — реалізуємо перевірку та Windows Update; утиліти виробників — етап 4.
