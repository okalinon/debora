# ADR-001: PowerShell 5.1 + WPF

**Статус:** прийнято · **Дата:** 2026-10-10

## Контекст
Утиліта має запускатися на свіжій Windows 10/11, часто на слабкому ПК без інтернету, без встановлення залежностей. Їй потрібен повний доступ до реєстру, служб, Appx і завдань.

## Варіанти
| Варіант | Плюси | Мінуси |
|---|---|---|
| **PowerShell 5.1 + WPF** | Є в кожній Windows; один файл; код читається як текст (довіра); WinUtil довів, що підхід працює | Повільніший старт; WPF з PowerShell — без компілятора й IntelliSense для XAML-прив'язок |
| PowerShell 7 + WPF | Сучасна мова, швидше | PowerShell 7 треба встановлювати |
| C# .NET 8 + WPF/WinUI | Швидкість, MVVM, тести, справжній `.exe` | Потрібен .NET runtime або self-contained ~70 МБ; бінарник важче перевірити користувачу |
| C++ / Win32 | Мінімальний розмір | Дорого в розробці |

## Рішення
PowerShell 5.1 + WPF. Модулі дій пишемо без залежності від UI, щоб за потреби перенести ядро в C# без зміни `tweaks.json`.

## Наслідки
- Обов'язкове збереження файлів у UTF-8 з BOM.
- Виконання — у фоновому runspace, інакше WPF зависає.
- `.exe` — лише обгортка (ps2exe) для зручності запуску.
